# Delphi 代码设计规范

编写 Delphi 代码时必须遵循以下设计规则。

## 总体原则

- 先思后行：写代码前思考隐患和可读性
- **易读性是代码质量的重要标准**，除非执行效率极为关键，否则易读性优先
- 修改代码前充分理解上下文和历史问题
- 遵循开闭原则：拓展业务首先考虑继承子类，而非修改原有代码

## 声明

- 遵循**最小可见性原则**：能放 implementation 就不放 interface，能 private 就不 public
- 声明类时显式写出 `published` 关键字，不依赖默认可见性
- 引用其他文件存在重名时，通过命名空间前缀访问
- 避免交叉引用（即使通过 interface 和 implementation 分开引用）
- 一个文件内仅包含一个主要的类，强关联类可同文件但建议拆分
- 声明顺序：常量 → 成员变量 → 函数 → 属性

## 函数设计

- 降低代码重复率，重复部分提取为函数
- **函数返回错误码时，调用者必须处理**
- 内部函数尽量少依赖外层变量
- 子函数嵌套不超过 **3 层**
- 函数逻辑缩进层级不超过 **3 层**（循环 + 判断，不计 with do）
- 函数职责单一：一个函数只完成一件功能
- 参数数量不超过 **3 个**，超过时封装为结构体
- 参数设计：
  - 不会被修改的参数加 `const`
  - 会被修改的参数加 `var` / `out`
  - 除作为返回值外，函数不应改动参数本身
- 扇出合理（通常 3-5，不超过 7）
- 减少递归调用，递归次数应可被正确评估

## 变量

- 不用或少用全局变量、全局函数
- **禁止使用魔数**（Magic Number），用常量/枚举代替
- **严禁使用未初始化变量作为右值**
- 成员变量在构造函数中初始化，初始化位置应统一
- 变量初始化位置离使用位置越近越好
- 避免不必要的强制类型转换，必须转换时先用 `is` 判断类型
- 内层变量不要与外层同名

## 类 / 接口

- 接口中不应包含未使用或不需要的方法，必要时拆分为多个接口
- 接口实现类优先从 `TInterfacedObject` 继承
- 不要利用同文件类共享 private 成员的特性，需隔离时用 `strict private` / `strict protected`
- 类成员函数访问本类成员变量时，直接访问字段而非 Property
- 模块内部不需要解耦时，直接使用类，不要使用接口

## 编程风格

- 成对操作（Create/Free, Lock/Unlock, Enter/Leave）必须确保完整执行，用 `try...finally` 保证
- Assert 仅用于调试，不用于运行时异常处理；Release 模式下应关闭 Assertions
- 界面输入必须有合法性限制和对应处理
- **禁止嵌套使用 with...do**，建议完全避免 with...do
- 不要拷贝大段代码，提取公共函数
- 重视编译器警告，提交代码前消除所有 error 和 warning

## 性能

- 循环体内工作量最小化，将与循环无关的操作移到循环外
- 多重循环中最忙的循环放在最内层
- 注意按值传递和按引用传递的效率差异
